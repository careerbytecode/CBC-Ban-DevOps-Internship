# Pods

## Definition

A **Pod** is the smallest deployable unit in Kubernetes. It can contain one or more containers that share the same network namespace, IP address, and storage volumes. Pods are typically managed by higher-level resources such as **Deployments** rather than being created directly.

---

## YAML Syntax

```yaml
apiVersion: v1
kind: Pod

metadata:
  name: <pod-name>
  labels:
    app: <app-name>

spec:
  containers:
    - name: <container-name>
      image: <image-name>:<tag>

      ports:
        - containerPort: <container-port>

      env:
        - name: <ENV_VARIABLE>
          value: "<value>"
```

---

## Syntax Explanation

| Field             | Description                                                                |
| ----------------- | -------------------------------------------------------------------------- |
| `apiVersion`      | Specifies the Kubernetes API version used to create the resource.          |
| `kind`            | Defines the type of Kubernetes resource (Pod).                             |
| `metadata`        | Stores metadata about the resource, such as its name and labels.           |
| `metadata.name`   | Specifies the unique name of the Pod.                                      |
| `metadata.labels` | Assigns labels used for identifying and selecting the Pod.                 |
| `spec`            | Defines the desired state and configuration of the Pod.                    |
| `containers`      | List of one or more containers that will run inside the Pod.               |
| `name`            | Name of the container within the Pod.                                      |
| `image`           | Docker/container image used to create the container.                       |
| `containerPort`   | Port on which the application inside the container listens.                |
| `env`             | Defines environment variables that will be available inside the container. |

---

## Example

The following example creates an Nginx Pod with one container listening on port **80** and an environment variable named **ENV**.

```yaml
apiVersion: v1
kind: Pod

metadata:
  name: nginx-pod
  labels:
    app: nginx

spec:
  containers:
    - name: nginx-container
      image: nginx:1.27

      ports:
        - containerPort: 80

      env:
        - name: ENV
          value: "Production"
```

---

## Create the Pod

Apply the YAML manifest to create the Pod.

```bash
kubectl apply -f pod.yaml
```

---

## Verify the Pod

Check whether the Pod has been created successfully.

```bash
kubectl get pods
```

View detailed information about the Pod.

```bash
kubectl describe pod nginx-pod
```

View the application logs generated by the container.

```bash
kubectl logs nginx-pod
```

---

## Delete the Pod

Delete the Pod using the YAML manifest.

```bash
kubectl delete -f pod.yaml
```

Alternatively, delete the Pod by name.

```bash
kubectl delete pod nginx-pod
```

---

## Expected Output

After creating the Pod, you should see output similar to:

```bash
$ kubectl get pods

NAME         READY   STATUS    RESTARTS   AGE
nginx-pod    1/1     Running   0          15s
```

---

## Key Points

* A Pod is the **smallest deployable unit** in Kubernetes.
* A Pod can contain **one or more containers**.
* Containers within the same Pod share:

  * Network namespace
  * IP address
  * Storage volumes
* Pods are **ephemeral**, meaning they can be recreated if they fail.
* In production environments, Pods are typically managed by **Deployments** rather than being created directly.
